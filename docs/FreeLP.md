# FreeLP position manager

FreeLP adapts the zero-fee accounting and settlement of BasePositions/FreePositions into a standalone ownerless ERC-721 manager. Existing production contracts and their source dependency graphs are unchanged.

Each NFT has exactly one immutable extension-free concentrated-liquidity PoolKey and tick range. Monotonically increasing 64-bit IDs are never reused. Creation initializes a missing pool and deposits atomically. Full-range liquidity is represented by the minimum/maximum valid ticks of a concentrated pool. Extensions and stableswap pool configs are rejected.

ERC-721 Enumerable exposes `totalSupply`, `tokenByIndex`, and `tokenOfOwnerByIndex`; `balanceOf` supplies the owner count. Enumeration order is unspecified, so clients sort locally and may batch RPC reads without a paginated UI. Pin reads to a single block for a consistent snapshot. `descriptor`, `positionAmounts`, `poolState`, and `quoteDeposit` supply the data needed to manage positions without an indexer. Core remains the authoritative source of live liquidity and fees. Ownership indexes update before safe-transfer callbacks and handle forwarding and transfer-to-self.

`tokenURI` returns base64 JSON with an embedded base64 SVG, generated entirely on-chain. Address labels deliberately avoid arbitrary ERC-20 metadata calls and external assets. Collection name/symbol are fixed. No owner, metadata setter, upgrade mechanism, fee setter, fee collector, or swap entrypoint exists.

`createPosition` and `addLiquidity` accept token maxima, minimum minted liquidity, and a deadline. Deposits are capped so aggregate position liquidity remains representable by int128. `withdraw` always collects fees and enforces minimum output amounts and a deadline; withdrawing zero liquidity collects fees only. `burn` requires no remaining liquidity or collectible fees. Standard NFT owner/operator authorization applies.

Nonpayable `multicall` batches ERC-20 operations and withdrawals. Native deposits are standalone payable calls; exact excess msg.value is returned in the same transaction. This deliberately avoids delegatecall reuse of msg.value across native deposits. All position mutation entrypoints are guarded against reentrancy, and NFT transfers are forbidden during settlement/refund callbacks. Safe-transfer receiver callbacks may forward NFTs after an ordinary transfer.

Validation: targeted tests cover principal/fee settlement, partial withdrawals, output limits/deadlines, standard enumeration and randomized mint/transfer/burn sequences, safe-transfer forwarding, native refund reentrancy, metadata decoding, code-size limits, invalid pool/range rejection, burn lifecycle, and atomic withdraw/burn batching. Gas measurements are in `snapshots/FreeLP.gas`.

Storage packing: the counter and both enumeration arrays use `uint64`, packing four IDs per array storage word. The counter explicitly rejects exhaustion at `2^64 - 1`, including after burns; public ERC-721 IDs remain `uint256`. Every enumeration index is bounded by the number of IDs ever minted. Each NFT uses three descriptor/index slots: `FreeLPPool` stores token0 plus the full 96-bit extension-free config, `FreeLPRange` stores token1 plus two signed 32-bit ticks, and the two 64-bit enumeration indexes share the third slot. Configs are validated before packing, so dropping the always-zero extension loses no information. Tick accessors sign-extend; fees and ticks retain their full supported ranges. This replaces four descriptor slots plus two separate index mapping slots; packed arrays add one slot per four IDs in each enumeration, excluding array lengths and the inherited ERC-721 owner/approval storage.

Packed arrays retain constant-time indexed ERC-721 enumeration, transfer, and burn. A doubly linked list could fit four 64-bit owner/global pointers into one word, saving approximately half an array slot per NFT after amortization (excluding list heads/tails). However, indexed enumeration would require a linear walk, making complete listing through the standard indexed getters quadratic in the token count. Packed arrays avoid that RPC cost and do not require a custom cursor interface.
